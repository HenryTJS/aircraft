# F-MOC 初步分析（2026-11-09）

> 数据：`E:\fmoc`；代码：`tools/profile_fmoc.py`；明细：`docs/fmoc_initial.csv`。
> 结论先行：**F-MOC 可以用来证明“未知数据集能接入并算出东西”，但它的 t85 不是 L1 口径，不能和 L1 的 89–94% 直接比。**

## 1. 数据与格式

| 项 | 内容 |
|---|---|
| 试件 | 7 个，`spec1`–`spec7` |
| 文件 | `E:\fmoc\ACOUSTIC\specN.pridb`，共 2.3 GB；另有 `DIC\` 约 15 GB（未分析） |
| 采集 | Vallen AMSY-6，8 通道，2 MHz，50 dB 阈值；`Time` 单位 100 ns（`ae_fieldinfo` 的 Factor=1e-7） |
| 命中 | `ae_data.SetType=2`；全部在 `Chan=1`；每件 0.81–4.44 M hits |
| 其它表 | `ae_data` 里还有 SetType=1（5.86 M 状态/参数行）、SetType=3（每通道 5,862 个标记/参数）；**不能把全表当 hits** |
| 试验 | CFRP 单向带 `[0/45/90/−45]`，400×45×2.28 mm；从完好跑到失效（数据说明） |

## 2. 方法

1. 只取 `SetType=2` 的 hits，读 `Time` 与 `Eny`；
2. 按 `Time` 排序，累积 hits / 累积能量；
3. `t_x` = 累积量达到终值 x%（x=50/85）时的时刻，**线性插值**；
4. 寿命分数 = `(t_x − t_first) / (t_last − t_first) × 100`，即**观测 AE 窗口内的时间分数**；
5. 不建 cycle 轴、不去 pause：F-MOC 文件里没有循环计数，`ae_markers` 只有少量 `Suspend/Resume`，无法可靠重建加载掩码。

复算：

```powershell
cd D:\aircraft
python tools\profile_fmoc.py --root E:\fmoc\ACOUSTIC --out docs\fmoc_initial.csv
```

## 4. 能读出什么

1. **t85 明显低于 L1（89–94%）**。这不是“F-MOC 的损伤更早”，而是三件事叠加：材料/结构不同、AMSY-6 阈值与 hit 定义不同、横轴是**时间**而不是 cycle；不能跨数据集比较。
2. **hit 数与能量给出的排序不一致**。spec2 用 hits 是 74.6、用能量是 86.0；spec3 反过来。说明“累计 hit 数”不是能量释放的稳定代理，单一口径不足以支撑损伤结论。
3. **时长/速率不能解释 t85**。spec4 时长 19.1 h、速率最低（34.7 hit/s），t85 却最低（58.8%）；spec2 最短（4.4 h），t85 居中（74.6%）。
4. **pause 未处理**。`ae_markers` 在 spec2 有 `17:03 Suspend / 17:05 Resume`，spec1 只有首尾 `Resume/Suspend`；如果试验中间还有未记录的空档，时间分数会被拉长，t85 会变。当前值是“观测窗口内的上界估计”，不是加载时间口径。

## 5. 边界（写报告必须带）

- 这是 **time-fraction t85**，`axis=time`，**不是** `docs/metric_standard.md` 的 cycle-fraction 标准；两者不能同轴、不能互相引用。
- 首/末 hit 不等于试验开始/失效时刻；数据说明写“到 end of life”，但文件里没有独立的失效标记。
- 7 个试件、同一实验室（TU Delft）、同一批次；**不是跨机构**。
- 只分析了 AE；DIC 15 GB 未动，也没有用 DIC 的位移/应变做交叉验证。
- F-MOC 的原生任务是“疲劳寿命预测”（论文的单调特征模型），t85 是我们外加的描述量，不是数据集标签。

## 6. 下一步（按性价比）

1. **补 cycle 轴**：从论文/试验记录找加载频率；若没有，用 DIC 时间戳推（每 50 s 一帧）并注明假设。
2. **建 pause 掩码**：用 `ae_markers` + hit 间隔（例如 >60 s 无 hit 视为停载）重建加载时间，重算 t85，和当前值对比；差值就是 pause 的影响。
3. **三口径对照**：hits / 能量 / 幅值阈值（如 Amp≥60 dB）各算一次，选一个物理上说得清的口径，写进 `scope.indicator`。
4. **作为“未知数据集”演示**：只写 `mapping.yaml`（列名、Time 因子、SetType、Chan），核心代码 0 行；输出 `axis=time`、`indicator=hits`，并在报告里明确“不可与 L1 比”。
5. **不要**用它做 RUL 标定：没有失效时刻、没有 cycle、只有 7 个试件。
