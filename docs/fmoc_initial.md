# F-MOC 初步分析（2026-11-09）

> 数据：`E:\fmoc`；代码：`tools/profile_fmoc.py`；明细：`docs/fmoc_initial.csv`。
> 结论先行：**F-MOC 可以用来证明“未知数据集能接入并算出东西”，但它的 t85 不是 L1 口径；而且 7 个试件的 AE 覆盖差异很大，`t85_full` 不能直接横向比。**

## 1. 数据与格式

| 项 | 内容 |
|---|---|
| 试件 | 7 个，`spec1`–`spec7` |
| 文件 | `E:\fmoc\ACOUSTIC\specN.pridb`，共 2.3 GB；另有 `DIC\` 约 15 GB（未分析） |
| 采集 | Vallen AMSY-6，8 通道，2 MHz，50 dB 阈值；`Time` 单位 100 ns（`ae_fieldinfo` 的 Factor=1e-7） |
| 命中 | `ae_data.SetType=2`；全部在 `Chan=1`；每件 0.81–4.44 M hits |
| 其它表 | `ae_data` 里还有 SetType=1（5.86 M 状态/参数行）、SetType=3（每通道 5,862 个标记/参数）；**不能把全表当 hits** |
| 试验 | CFRP 单向带 `[0/45/90/−45]`，400×45×2.28 mm；从完好跑到失效（数据说明） |

## 2. 方法

1. 只取 `SetType=2` 的 hits，读 `Time` 与 `Eny`；
2. 按 `Time` 排序，累积 hits / 累积能量；
3. `t_x` = 累积量达到终值 x%（x=50/85）时的时刻，**线性插值**；
4. 寿命分数 = `(t_x − t_first) / (t_last − t_first) × 100`，即**观测 AE 窗口内的时间分数**；
5. **覆盖指标**：
   - `t99` = 累积 hits 达到 99% 的时间分数；
   - `last10` = 最后 10% 时间窗内的 hit 占比；
   - `t85_active` = `t85_full / t99 × 100`，即“在 99% 命中覆盖的活跃窗内”的敏感性值。
6. 不建 cycle 轴、不去 pause：F-MOC 文件里没有循环计数，`ae_markers` 只有少量 `Suspend/Resume`，无法可靠重建加载掩码。

复算：

```powershell
cd D:\aircraft
python tools\profile_fmoc.py --root E:\fmoc\ACOUSTIC --out docs\fmoc_initial.csv
```

- `t85_full`：中位 **74.55%**，范围 **58.78–84.39%**。

## 4. 关键发现：低 t85 主要是“尾部静默”的覆盖问题

`spec4` 最典型：

- `t85_full = 58.78%`，但 `t99 = 70.67%`，最后 10% 时间窗内 **0 个 hit**；
- 第 8、9 个十分位也几乎为 0（实测：第 8 段 42,074 hits、第 9 段 0、第 10 段 1）；
- 也就是说，**AE 记录在约 71% 处就基本停了，而观测窗口一直延续到 100%**；`t85_full` 的分母被这段静默拉长，数值自然偏低。
- 按活跃窗归一化后，`t85_active = 83.17%`，与其它试件（81–86%）一致。

其它试件同样有不同程度的尾部稀疏：spec3（t99=85.3，last10=0.07）、spec5（87.8，0.18）、spec2（90.1，1.09）。只有 spec1/spec6 接近满覆盖（t99≈98%，last10≈8%）。

**这解释了两件事：**

1. `t85_full` 的 58.8–84.4% 不是“损伤更早”，而是 **AE 覆盖不一致**；
2. 直接拿 `t85_full` 和 L1 的 89–94% 比，是把“覆盖差异”误读成“物理差异”。

但 `t85_active` 也只是**敏感性值**：它假设“AE 停了以后试验还在继续”，而文件里没有试验终点的独立真值。要把它变成 claim，需要 test-end（DIC 最后一帧时间、MTS 停机时刻或循环计数）。

## 5. 还能读出什么

1. **hit 数与能量给出的排序不一致**：spec2 用 hits 是 74.6、用能量是 86.0；spec3 反过来（71.1 vs 60.5）。说明“累计 hit 数”不是能量释放的稳定代理，单一口径不足以支撑损伤结论。
2. **时长/速率不能解释 t85**：spec4 时长 19.1 h、速率最低（34.7 hit/s），`t85_full` 最低，但这是覆盖问题；spec2 最短（4.4 h），`t85_full` 居中。
3. **不能和 L1 同轴**：材料/结构、AMSY-6 阈值与 hit 定义、时间轴 vs cycle 轴，三重不同。

## 6. 边界（写报告必须带）

- 这是 **time-fraction t85**，`axis=time`，**不是** `docs/metric_standard.md` 的 cycle-fraction 标准；两者不能同轴、不能互相引用。
- 首/末 hit 不等于试验开始/失效时刻；数据说明写“到 end of life”，但文件里没有独立的失效标记。
- `t99` 只是“99% 命中覆盖”的代理，不是“试验终点”；`t85_active` 是敏感性分析，不是标准值。
- 7 个试件、同一实验室（TU Delft）、同一批次；**不是跨机构**。
- 只分析了 AE；DIC 15 GB 未动，也没有用 DIC 的位移/应变做交叉验证。
- F-MOC 的原生任务是“疲劳寿命预测”，t85 是我们外加的描述量，不是数据集标签。

## 7. 下一步（按性价比）

1. **补 test-end**：从 DIC 最后一帧时间或试验记录拿停机时刻；算 `coverage = t99 / test_end`，再决定 `t85_full` 能不能用。
2. **补 cycle 轴**：从论文/试验记录找加载频率；没有就用 DIC 时间戳推（每 50 s 一帧），并注明假设。
3. **建 pause 掩码**：用 `ae_markers` + hit 间隔（如 >60 s 无 hit）重建加载时间，重算，和当前值对比；差值就是 pause 的影响。
4. **三口径对照**：hits / 能量 / 幅值阈值（如 Amp≥60 dB）各算一次，选一个物理上说得清的口径，写进 `scope.indicator`。
5. **作为“未知数据集”演示**：只写 `mapping.yaml`（列名、Time 因子、SetType、Chan、test_end），核心代码 0 行；输出 `axis=time`、`indicator=hits`、`coverage`，并在报告里明确“不可与 L1 比”。
6. **不要**用它做 RUL 标定：没有失效时刻、没有 cycle、只有 7 个试件。
